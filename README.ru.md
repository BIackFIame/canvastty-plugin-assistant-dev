# CanvasTTY Assistant — Помощник

> **Нужен CanvasTTY 1.8 или новее** (plugin API v2: сервисы плагинов, участие в запуске, решающие хуки с полями `profile`/`canAsk`, инструменты плагинов, события сессий, значки и действия на окнах). Используются только API, которые в CanvasTTY уже есть; в ядре нет ничего специально для этого плагина. В CanvasTTY 1.7.0 и раньше этих точек расширения нет, поэтому установка там не пройдёт проверку манифеста.

[English](README.md) · [Русский](README.ru.md)

«Помощник» для [CanvasTTY](https://github.com/howdeploy/CanvasTTY): маленькая модель решений, которая проверяет
команды агентов до запуска, разбирает задачу окна и помогает оркестраторам (выбор модели, сценарии, доска задач,
сигнал зацикливания, отчёт о сессии). Что он применяет, решаете вы: проверка команд сначала **выключена** — и при
новой установке, и при обновлении, — и ни одна модель не вызывается, пока вы её не подключите. Если сохранённые
настройки не удалось прочитать при запуске, проверка остаётся выключенной, поверх них ничего не сохраняется, а
Помощник сам читает их ещё раз.

## Настройки

Настройки → Плагины → Ассистент CanvasTTY → **Настройки**, пять переключателей:

| Настройка | Значения | По умолчанию |
|:--|:--|:--|
| Проверка команд | Строго (всё, кроме команд чтения, ждёт вас) · Базовые правила (блокирует то, что запрещают жёсткие правила: повышение прав, загрузку прямо в оболочку, удаление или запись вне проекта; остальное выполняется с подсказкой на окне) · Выкл. Настройки, которые не совпадают ни с одним уровнем (например, режим «Обучение» старой версии), показаны как **Особая**, только для чтения, пока вы не выберете уровень. | Выкл |
| Доверять задаче оркестратора для новых файлов его субагентов | вкл/выкл: **цепочка доверия** (ниже) | выкл |
| Автоматический выбор модели | вкл/выкл: инструмент `route` предлагает провайдера, модель и усилие | вкл |
| Сигнал зацикливания | вкл/выкл: значок `цикл?`, когда окно за один ход повторяет одну команду, а правок файлов не видно | вкл |
| Сценарии | вкл/выкл: инструменты сценариев и карточка «Просмотр сценария» | вкл |

Модели решений не обязательны и настраиваются на своей странице (**Модели решений…** внизу).

**Цепочка доверия.** Если она включена, субагент может без вопроса создать новый файл в проекте, когда:
- задача оркестратора над ним — ваша;
- файл новый и его содержимое видно целиком;
- это не секрет, не защищённый путь и не команда;
- проверка достаточно уверена, что файл нужен для задачи: не меньше 95%, или 75%, если доверенная задача называет этот файл, файл ложится в папку субагента (или в папку, названную в задаче) и все риски низкие.

Задачу оркестратора Ассистент считает **вашей** только по тому, что до него доходит:
- поле **«Задача»** при запуске (Дополнительно → Ассистент CanvasTTY). CanvasTTY ограничивает его 200 символами;
- или ходы оркестратора на модели «Авто (Jev)».

**Тесты в цепочке доверия.** Она же позволяет такому субагенту запустить свои тесты, когда команда — простой известный запуск (`node --test <файлы>`, `pytest <файлы>` или `npm`/`pnpm`/`yarn test`, чей package.json проверка видела или git хранит без изменений, со скриптом test из простого запуска и без pre/post-скриптов и настроек менеджера пакетов), а каждый файл, который она выполняет или импортирует, проверка разрешила целиком в этом окне (содержимое то же) или он закоммичен и не изменён; проверка должна быть уверена хотя бы на 75%, что это служит задаче, все риски, кроме скрытого эффекта, — не выше 10%. Синтаксис оболочки, пакеты, динамические импорты, `go test` и `cargo test` по-прежнему решаете вы. В журнале проверки — `trust-chain-test`.

**Составные команды в цепочке доверия.** `a; b` или `a && b` (и ничего больше: без каналов, перенаправлений, подоболочек и `&`) разрешается, когда каждая часть разрешена сама по себе (чтение, просмотр или свои тесты). Правка OpenCode со старым и новым текстом считается переписыванием своего файла окна, когда CanvasTTY передаёт этот текст (1.8.2 передаёт только новый).

**Просмотр и исправления в цепочке доверия.** Такой субагент может также выполнять простой просмотр внутри проекта (`pwd`, `ls`, `cat`/`head`/`tail`/`wc` файлов, `git status`/`diff`/`log` с простыми флагами в репозитории, чья собственная настройка не запускает пейджер или программу сравнения; никогда — секреты, защищённые пути и `.git`) и переписывать файл, который сам записал раньше, если с тех пор его никто не менял: новое содержимое целиком или правка со старым и новым текстом, которая проверяется как весь итоговый файл, — по тем же порогам, что и новый файл, и со всеми прочими рисками не выше 10%. Правку OpenCode в том виде, как её передаёт CanvasTTY 1.8.2, нельзя отличить от частичной, её по-прежнему решаете вы. В журнале — `trust-chain-inspect` или `trust-chain-own-file`.

Для длинной задачи впишите в поле «Задача» её первую строку (с именами файлов, которые создадут субагенты), а подробности — в первое сообщение оркестратору. Без поля «Задача» у оркестратора на аккаунте модели или на собственном входе цепочки доверия нет, и записи его субагентов, как и раньше, решаете вы.

## Для оркестраторов

На HOME, в док, в запускатель и в собственные настройки CanvasTTY ничего не добавляется. Оркестратор получает
инструменты (`canvastty-assistant__<имя>`), окна — три действия в меню, у плагина две карточки на холсте, которые
открываются из Настройки → Плагины → Ассистент CanvasTTY.

- **`route`** (и **`pick_route`** — имя, на которое указывает `list_providers().note`) `{ task, providers?,
  accountRoutes?, prefer?, orchestrate? }`: где запустить субагента — CLI, вход (ваша подписка в этом CLI, план для
  кода, аккаунт модели, «Авто»), модель и усилие — и до двух запасных вариантов, у каждого значения `spawn` для
  `spawn_agent` CanvasTTY, пояснение и оценка (в долларах или как доля окна подписки). Передайте
  `list_providers().providers` и строки `list_routes` плагина Accounts. Модели сравниваются по измеренной оценке
  каталога «Авто» для типа задачи (задачу читает Jev, если подключён, иначе правила по словам), затем по цене или доле
  окна; подписка с запасом выше вашего резерва бесплатна и предпочитается в пределах окна качества. Значения spawn
  называют каждый плагин, который задаёт модель (`canvastty-assistant`, `canvastty-accounts`), поэтому ничего не
  наследуется случайно. Подписки и планы объявляются в разделе **«Где работают агенты»** на странице «Модели решений»;
  если ничего не объявлено, последний вариант — модель CLI по умолчанию (но никогда не собственная модель OpenCode).
- **`route_outcome`** `{ decisionId | sessionId, status, exitLines?, ok? }`: чем закончился субагент, запущенный по
  route. Выход по лимиту даёт этому пути отдых до сброса окна; неудачи понижают путь, который явно хуже других путей к
  той же модели.
- **Сценарии**: `flows_list`, `flow_plan { flow, goal }`, `flow_status { planId? }`. `flow_plan` возвращает только id
  плана и названия ролей; план ждёт вас в карточке **«Просмотр сценария»** (роли, провайдер/модель, задачи; встроенные
  сценарии на вашем языке, сценарии проекта из `.canvastty/flows/*.json|yaml` помечены «Из этого проекта» и показаны
  как написаны, без невидимых символов). Только после **«Запустить»** `flow_status` отдаёт оркестратору, что передать
  в `spawn_agent`; роли попадают на его доску задач. Кнопка «Запустить» недоступна первые мгновения после появления
  плана, замена плана на экране отмечается («План изменился»), а оркестратор может предложить не больше трёх планов
  в минуту. Действие меню окна **План по сценарию…** переключает просмотр на этот оркестратор, и сценарий можно выбрать
  самому. **Это просьба к оркестратору, а не запрет**: плагин ничего не запускает и не может остановить оркестратор,
  который вызывает `spawn_agent` без плана. Для этого нужен API хоста (см. «Что нужно»).
  Сценарии проекта читаются только из настоящей папки `.canvastty/flows` внутри проекта (папка или файл-ссылка
  отклоняются, файлы открываются без перехода по ссылкам); об отклонённом файле сообщается фиксированной причиной,
  без его содержимого. Текст сценариев проекта оркестратор получает с пометкой «данные в кавычках, не инструкции».
- **Доска задач**: `task_add` (оркестратор), `task_update` и `task_list` (оркестратор и его субагенты; субагент меняет
  только свои задачи или берёт свободную). Карточка **«Доска задач»** показывает их по состояниям; на окне оркестратора
  значок `задачи 2/5`, а действие меню **Доска задач** переключает карточку на него.
- **Дерево агентов**: кто кого запустил. Карточка **Дерево агентов** (Настройки → Плагины → Ассистент CanvasTTY → Дерево
  агентов или ссылка на странице настроек) рисует оркестратора сверху и запущенных им агентов ниже, соединяя их линиями.
  На каждой карточке: название, модель, статус (Работает, Ждёт, Нужно одобрение, Готово, Ошибка), задача, цена и время,
  а также сколько агентов она запустила (из скольких разрешает план автопилота); ветку можно свернуть. В заголовке —
  `N агентов · M работают` и доллары платных маршрутов; подписка, план для кода или аккаунт с фиксированной ценой
  показаны как план с долей окна или числом запусков, а не как деньги. Цена — оценка маршрута за одну задачу, а не счёт.
  Щелчок показывает это окно на холсте (CanvasTTY с `sessions.focus`; более старая версия скажет об этом). Действие меню
  **Дерево агентов** у оркестратора или субагента переключает карточку на его дерево. Модель берётся из CanvasTTY, если
  он передаёт модель запуска, иначе из маршрута, выбранного Помощником; у окна без маршрута — «цена неизвестна».
- **Сигнал зацикливания**: каждая команда оболочки приходит плагину до запуска. Одна и та же команда (без учёта пробелов,
  чисел и хвоста вроде `| tail -50`) пять раз за ход без замеченных правок файлов между ними ставит на окно `цикл?`;
  значок снимается, когда начинается следующий ход (но не от короткого мигания состояния). Правки через оболочку
  (`sed -i`, перенаправления и heredoc в файл, `tee`, `cp`/`mv`, форматтеры…) считаются правками; ожидание (`sleep`,
  `watch`, `git status`, `gh pr checks`…) не считается. Результаты команд плагинам не видны, провайдеры без решающего
  хука не видны вовсе. Только подсказка.
- **Отчёт** (меню любого агента): время запуска, время работы, ходы, состояние и код выхода, субагенты, сколько команд
  увидено и что проверка отклонила или передала вам, сигналы цикла и задачи. Токены и стоимость плагинам недоступны.

У окна один значок на плагин; показывается самый важный сигнал (цикл, ожидающий сценарий, проверка, задачи, разбор).

**Что хранится**: в папке данных плагина `harness/plans.json` и `harness/boards.json` открытым текстом лежат планы
сценариев (цель, названия ролей и задачи) и доски задач (заголовки, подробности, заметки) — ваши слова и слова агентов,
как написаны. Планы удаляются через сутки, при закрытии окна оркестратора или когда CanvasTTY это окно больше не
показывает; доски — вместе с оркестратором. Одобрение с диска не читается: после перезапуска план нужно одобрить
заново. Сигнал зацикливания хранит только хеши; отчёт — счётчики, без текста команд.

## Что делает

- **Проверка команд** (decision hook). Перед командой оболочки или записью файла локального агента сначала отвечает
  базовая защита CanvasTTY, потом Помощник: белый список чтения (`git status`, `ls`, `rg`…), девять вопросов «да/нет»
  маленькой модели, в спорном случае — большая модель второго просмотра, которая читает и скрипты или diff, которые
  запускает команда; иначе решаете вы. Скрипт, написанный агентом в этой сессии, без вас не разрешается никогда.
  Действие сверяется с задачей окна: вписанной в запускателе, а при «Модель: Авто (Jev)» — с каждым новым ходом
  пользователя, который видит маршрутизатор (только в памяти, по классу данных окна). Задача субагента считается
  вашей, только если вы написали её слово в слово; иначе действие сверяется с вашим запросом окну выше.
- **Режимы** для каждого сценария: Выкл, Обучение (ответы только записываются), Подсказки (значок на окне, ничего не
  навязывается), Авто (может спросить вас или отказать; разрешает только то, что прошло проверку на ваших оценках
  «верно/неверно», и только если в CanvasTTY вы разрешили плагину разрешать). Любая ошибка, таймаут или нет ключа —
  решаете вы, никогда не «разрешено».
- **Разбор задачи при запуске**: впишите задачу в запускателе (Advanced → Use CanvasTTY Assistant). Помощник
  отметит рискованные задачи для строгой проверки и покажет совет значком (сложность, вид, worktree или контейнер,
  сильная модель).
- **Инструменты оркестратора**: `canvastty-assistant__recommend` (совет до `spawn_agent`) и
  `canvastty-assistant__review_status`.
- **Агенты, которые не могут спросить**: спросить вас из хука может только Claude Code. Для остальных агентов проверка
  в режиме Авто, которая спросила бы вас, отвечает отказом с причиной и тем, что делать вместо этого; проверка, которая
  не успела, в окне с профилем, который и так спрашивает вас (normal, plan), оставляет решение собственному запросу CLI.
- YOLO и изоляция — правила самого CanvasTTY (ваше подтверждение для каждого CLI, слой изоляции для неручных агентов);
  прежняя опция «YOLO только в изоляции», считавшая worktree изоляцией, убрана.
- **Проверка данных**: Строго, Только предупреждать или Выкл; что может уйти с компьютера (только служебные признаки,
  тексты до D1 или D2); ваше доверие к каждой удалённой модели. Локальной Ollama доступно всё; ключи вырезаются до отправки.

## Модели решений

- **Jev** через TypeSafe, OpenRouter (без хранения данных) или Vercel: нужен ключ.
- **Laya** и сервер **Eikos** `serve.py` на вашем компьютере или по https.
- **Ollama**: любая локальная instruct-модель (например, `qwen3.5:9b`), ответ читается по logprobs букв вариантов;
  большая локальная модель (например, `gpt-oss:20b`) — второй проверяющий.

Ключи со страницы настроек сразу уходят в секреты плагина и больше не показываются; читает их только сервис, в
момент вызова, привязанными к адресу, для которого они сохранены, а CanvasTTY маскирует их во всём, что читают агенты.
«Проверить» отправляет фиксированный синтетический набор вопросов (без ваших данных).

## Модель: Авто (Jev) (OpenCode)

В окне запуска **Дополнительно → Ассистент CanvasTTY → Модель: Авто (Jev)** запускает окно OpenCode на модели, которую
Помощник выбирает на каждом новом ходе из вашего списка. «Модель» в окне запуска оставьте по умолчанию и не выбирайте
аккаунт модели (аккаунт и «Авто» в одном запуске отклоняются: оба настраивают OpenCode).

- **Где работает**: пока окно на «Авто», служба Помощника слушает **только 127.0.0.1** (порт сохраняется между
  перезапусками). У каждого запуска свой случайный ключ `sk-ctty-…`; служба хранит только его хеш; ключ перестаёт
  работать, когда окно закрыто или перезапущено, а порт закрывается, когда «Авто» не пользуется ни одно окно.
  Запросы от веб-страниц (заголовок `Origin`) и на другое имя хоста отклоняются.
- **OpenCode** получает файл конфига в папке своего запуска: один провайдер на этот порт, `model` и `small_model` на
  нём и `enabled_providers` только с ним, поэтому OpenCode Zen и другие провайдеры из вашего конфига не используются.
  Проект, чей собственный конфиг OpenCode выбирает модели или провайдеров, отклоняется (у OpenCode конфиг проекта
  главнее). Контейнеры и удалённые хосты отклоняются (они не достают до 127.0.0.1 этого компьютера); другие CLI позже.
- **Решение по данным**: на каждом новом ходе Jev (разбор задачи, когда он в режиме «Подсказки» или «Авто» на странице
  «Модели решений») читает последний текст пользователя за 2,5 с и называет **тип задачи** (код, ревью, исследование,
  тексты, общение) и **сложность** (маленькая, средняя, большая); «маленькая» требует вероятности ≥ 0,5 на двух самых
  лёгких уровнях (выбрано по 40 размеченным задачам живого прогона: ни одна средняя или большая задача не стала
  маленькой; 0,7 для исследования и ревью, а ходы окна-оркестратора маленькими не бывают), иначе ход средний. Без Jev то и другое дают словесные правила (никогда не «уверенно»). Среди разрешённых
  вами моделей, доступных сейчас (не остывают, им доверен класс данных окна, хватает контекста, укладываются в
  пределы), отвечает **самая дешёвая модель, чья оценка каталога для этого типа задачи не более чем на несколько баллов
  ниже лучшей**: **«Сбалансированно»** — 8 / 5 / 3 балла на маленьком / среднем / большом ходе, **«Дешевле»** — 15 / 10 /
  5, **«Лучше»** — нисколько; в этих пределах предпочитается и меньший уровень рассуждения, кроме больших ходов. Jev
  отвечает не более чем на 10 ходов в минуту на окно (60 на все окна), дальше — словесные правила. Модель без оценки никогда не побеждает модель с оценкой;
  если оценок нет ни у кого, решают ваши ручные уровни, иначе известная модель средней цены. Шаги с инструментами
  остаются на модели хода; заголовки и сводки — на самой дешёвой и без вопросов — примерно одно решение на ход, а не на
  каждый вызов модели. Каждое решение записывается с типом, сложностью, моделью, уровнем рассуждения, оценкой и её
  источником, ценой, кодом причины и компромиссом (модель с лучшей оценкой, её оценка и цена, допустимые баллы) — без
  текста.
- **Ваши подписки из Accounts** (CanvasTTY с запросами через другие расширения; определяется сам, старый CanvasTTY
  ничего не покажет): на странице «Модели решений» раздел *Учётные записи других расширений* показывает записи, которые
  CanvasTTY разрешает Auto. Отметьте запись в Accounts, разрешите Assistant в Настройки → Агенты → Нативный код
  расширений → CanvasTTY Accounts, нажмите **Использовать в Auto** и выберите доверие. Каждый ход на ней идёт через
  CanvasTTY, который сам подставляет ключ записи: Auto его не видит. Подписка не тратит лимиты Auto в долларах;
  исчерпанный план (Accounts отказывает), 429 или снятое разрешение переключают на другую модель с паузой, как у любого
  провайдера. OpenRouter среди них не бывает. Используются только записи, совместимые с OpenAI (Chat Completions);
  запись на API Anthropic видна, но не используется.
- **Каталог**: models.dev (модели, цены, пределы), Artificial Analysis и LiveBench (измеренные оценки по точной модели
  и уровню рассуждения) и список моделей OpenRouter читаются с фиксированных адресов HTTPS (без текста задач и ключей),
  хранятся на диске и обновляются в фоне (раз в неделю; список OpenRouter — раз в день), пока включён поставщик, или
  кнопкой **«Обновить сейчас»**. Оценка относится к одной точной модели и уровню рассуждения и не переходит к другому
  варианту; модель без собственной строки остаётся неизвестной. Старые оценки учитываются (с пометкой), цены старше 7
  дней не сравниваются. Измеренные строки поставляются с плагином для компьютера, который ещё не был в сети. Страница
  Artificial Analysis теперь содержит полные строки только для моделей своего графика по умолчанию, поэтому обновление,
  вернувшее меньше половины известных строк, сохраняет прежние строки, которых в нём нет.
- **OpenRouter — только для Jev.** «Авто» никогда не отправляет вызовы моделей на openrouter.ai (в любом написании адреса, на его поддомены или на его IP-адрес): такого поставщика нельзя добавить или включить, сохранённый раньше остаётся выключенным, пути субагентов через него не предлагаются, а маршрутизатор отказывает ему при каждом вызове. Если другого поставщика нет, ход «Авто» завершается сообщением, которое предлагает запустить окно на модели агента.
- **Поставщики** (страница «Модели решений»): **OpenRouter** (свой ключ или ключ Jev · OpenRouter) предлагает весь свой
  список подходящих моделей (инструменты, текст, фиксированная цена; без вариантов `:free`) с контекстом и ценами
  OpenRouter; модель с измеренными уровнями рассуждения предлагается на каждом из них, и «Авто» отправляет этот уровень
  (`reasoning.effort`), если CLI не задал свой. **Совместимые с OpenAI** адреса принимают ваши точные id моделей; цены —
  из models.dev, если он знает этот адрес, или ваши. В строке модели видны контекст, цена и оценка (только чтение),
  отметка «использовать» и по желанию ручной уровень и уровень рассуждения. Доверие к поставщику: D0–D2; D3 — только
  серверу на этом компьютере. Ключи только записываются и привязаны к адресу поставщика. Запрос уходит дальше с заменой
  одного `model` (и уровня рассуждения, см. выше); 404/408/409/425/429/5xx, ошибка соединения или тайм-аут **до первого
  байта** переключают на следующую модель и дают сбойной остыть (у 429 учитывается `Retry-After`); так же — ответ 400 о неизвестном id
  модели («is not a valid model ID» у OpenRouter, остывание 15 мин); другой неверный запрос (400) возвращается как есть; оборвавшийся на середине поток заканчивается ошибкой и никогда не повторяется.
- **Зависшие ответы**: служебные сообщения «я жив» не считаются продвижением (предел простоя 90 с), а начавшийся ответ длится не больше 120 с (240 с при xhigh и выше), затем завершается с ошибкой; вызов, по которому поставщик так и не сообщил расход, учитывается по оценке (с пометкой).
- **Пределы**: на окно и в день в долларах, резервируются до каждого вызова, поэтому параллельные вызовы их не
  проскочат; считаются по стоимости от поставщика (OpenRouter её сообщает) или по вашим ценам. Исчерпанный предел — 402.
- **Несколько моделей на сложных ходах** (страница моделей решений; консенсус по умолчанию **«Авто»**, «лучший из N»
  **выключен**): сложный текстовый ход (уровня дизайна или исследование/ревью/тексты большого уровня; никогда шаг
  инструмента, заголовок, окно оркестратора или разговор, где уже вызывались инструменты) может уйти 2–3 чуть более
  слабым моделям разных производителей (сначала другие поставщики; адрес с фиксированным тарифом на странице
  маршрутизации — не больше 2 одновременно), а их черновики сводит сильная модель, и её ответ идёт в CLI потоком. В
  режиме «Авто» — только когда это окупается: оценка судьи + 1,5 балла за каждого другого производителя (не больше 3)
  − оценка одной модели − стоимость («Дешевле» ×3, «Сбалансированно» ×1, «Лучше» ×0 за удвоение) − ожидание (½ за
  удвоение, только при известных скоростях) > 0; **«Всегда»** эту проверку пропускает. **«Лучший из N»** сравнивает и
  оставляет один черновик. Все черновики и судья сначала резервируются в пределах лимитов и предела на ход ($1).
  Черновик с вызовом инструмента делает ход обычным (ответ одной модели без изменений, остальные останавливаются);
  упавший или опоздавший черновик отбрасывается; если судья не ответил, берётся лучший черновик. Каждое решение
  записывает исходы черновиков (без текста); путь, упавший в половине из ≥ 10 раз, больше не спрашивается.
- **Скорость**: измеренные Artificial Analysis скорость вывода и время до первого фрагмента для точной модели и уровня
  рассуждения хранятся в каталоге (публичный список OpenRouter их не даёт). Они входят во время на планах на странице
  маршрутизации и в ожидание в правиле выше; неизвестная скорость нейтральна.
- **Субагенты**: «Авто» — один из путей `route` для субагентов OpenCode (`launchOptions: {"canvastty-assistant":
  {"model": "auto"}}`, без модели); класс данных субагента никогда не ниже, чем у родителя.
- **Приватность**: запросы уходят только поставщику, который отвечает; Jev получает только последний текст
  пользователя, через те же проверки данных, что и всё остальное. Журнал маршрутизации хранит хеши, модели, уровни,
  статусы, токены и стоимость — без текста. Значок окна показывает текущую модель, когда она меняется (любой другой
  сигнал Помощника важнее).
- **Известное ограничение**: собственная оболочка агента может прочитать свой ключ и обратиться к маршрутизатору сама;
  тогда она тратит не больше предела этого окна и только через тот же список моделей.

## Автопилот «Авто (Jev)»

Выберите в окне запуска роль и **«Модель: Авто (Jev)»**; остальное в пределах ваших объявлений решает Jev.

- **Claude Code и Codex** работают в «Авто» на **собственном входе**: Помощник добавляет только модель и уровень рассуждения, выбранные Jev на объявленной вами подписке этого CLI, и закрепляет адрес поставщика (`ANTHROPIC_BASE_URL=https://api.anthropic.com`; у Codex `model_provider="openai"`). Без прокси и без ключа. Если у подписки не осталось запаса сверх вашего резерва, запуск отклоняется с причиной; на платный путь он никогда не переносится. Без объявленного плана используется модель CLI по умолчанию. OpenCode остаётся на прокси «Авто» (только не-OpenRouter поставщики).
- **`autopilot_plan`** (для оркестраторов): Jev читает задачу (`task.route` и новый `task.shape`: структура и число частей), и план говорит «сам», «оркестрировать N» или «глубоко», стратегию и бюджет. При уверенности ниже 0,6 решают словесные правила; неясная большая задача получает не больше 3 частей.
- **Каждый субагент окна «Авто» проходит через `pick_route`.** Его ответ несёт одноразовое значение в параметре `model` Помощника, привязанное к этому оркестратору, этому CLI и этому решению на 10 минут и учитываемое в плане. Субагент без него (унаследованный или названный), с использованным, просроченным или чужим значением или сверх плана отклоняется с подсказкой; оркестратор тогда его маршрутизирует. Запуски вне дерева «Авто» и все запуски, которые вы делаете сами, этим не отклоняются.
- **Пути планов OpenCode** (`zai-coding-plan/…`) закрепляются: запуск получает одного поставщика для модели и для маленькой модели (заголовки, сводки).
- **Серверы** (Модели решений → Дополнительно → Где работают агенты; по умолчанию выключено): `start_leaf` запускает независимую листовую задачу на объявленном вами сервере (имя — как в плагине Environments), на собственном входе CLI на сервере, в пределах его лимита; `leaf_status` сообщает её состояние. Лист не может запускать субагентов. Нужны `sessions:launch` и `sessions:control` (проверка при установке).
- **Этап 2, где он есть в CanvasTTY (проверяется во время работы; старые версии работают как на этапе 1):**
  - **Запуск совпадает со своим маршрутом.** Помощник объявляет ограниченную политику запуска (`"policy": { "scope": "own-trees" }`): CanvasTTY спрашивает его только перед запуском субагента в дереве, в которое Помощник внёс параметры или которое он запустил, и никогда — перед запуском, который вы делаете сами. Где CanvasTTY показывает службе запуска, что просит запуск (модель, усилие, выбранные плагины и поля, которыми с ней делится другой плагин), субагент дерева «Авто» запускается только с CLI, моделью и усилием своего маршрута и с аккаунтом Accounts, который выбрал маршрут (когда плагин Accounts делится с Помощником своим полем `account`). Отклоняются и субагент на другом CLI без своего маршрута (в том числе когда оркестратор работает в Claude Code без объявленного плана, то есть без модели от Помощника), и «внук» на другом CLI, и субагент ребёнка, направленного как одна задача (не с `orchestrate: true`). Каждый отказ говорит оркестратору вызвать `pick_route`. Пока служба Помощника не работает, ждут или отклоняются только такие субагенты; ваши собственные запуски от неё никогда не зависят. CanvasTTY без ограниченной формы получает сборку без политики (проверки этапа 1, ничего нового не отклоняется); неограниченную политику плагин не объявляет никогда. Субагент «листа» на том же CLI отклоняется везде, где CanvasTTY показывает, что просит запуск: он наследует параметры Помощника.
  - **Запустить с «Авто (Jev)»** (страница настроек Помощника, одно действие): напишите задачу и папку проекта; Jev читает задачу, а код выбирает, где работает оркестратор: CLI, вашу объявленную подписку или план для кода либо аккаунт модели или пул Accounts (как их передаёт Accounts после вашего разрешения; иначе из тех, что за последние сутки показал `list_routes` оркестратора), среди CLI, которые CanvasTTY показывает установленными, модель и усилие, а с «На одном из ваших серверов» (только когда серверы включены) — сервер, где есть место, на его собственном входе. Помощник запускает его с пометкой «Запустил» Помощник, один раз привязывает к этому решению с числом детей из плана и печатает задачу и план первым сообщением. Нужно ваше разрешение **Может запускать оркестраторов** для Помощника (Настройки, раздел «Нативный код расширений»). Без него или в CanvasTTY, где плагины не могут запускать оркестраторы, ничего не запускается, и страница подсказывает: запустите оркестратор сами с моделью «Авто (Jev)». Маршрут через OpenRouter — никогда.
- Пока нет (изменения CanvasTTY): субагенты на серверах, выбор CLI окна, которое вы запускаете сами.

## Главный агент

Одно окно, с которым вы говорите; оно передаёт работу вашим проектам (дизайн «Главного агента», этап 0, только плагины).

- **Запуск:** страница Помощника → «Главный агент» → **«Запустить главного агента»**, пункт **«Главный агент»** первым в окне запуска HOME (CanvasTTY с пунктами запуска плагинов) или плитка **«Main agent»** на HOME (добавьте её один раз: Настройки → Оформление → Состав HOME). Повторный щелчок показывает открытое окно, второго не запускает. Он работает в своей маленькой папке `~/CanvasTTY/main-agent` (в её `AGENTS.md` и `CLAUDE.md` — его инструкция) на самом сильном маршруте, который выбирает Jev среди CLI, чьи агенты видят инструменты плагинов (Claude Code, Codex, Qwen Code, OpenCode), сначала маршруты с фиксированной оплатой. Сам он субагентов не запускает.
- **Мои проекты:** папки, которые вы добавляете на странице Помощника сами (полный путь; папки открытых окон предлагаются). Помощник проверяет каждую папку (существующий каталог; не корень диска, не сама домашняя папка, не системная папка, не папка с ключами или входами, не данные CanvasTTY) и проверяет снова при запуске проекта. Главный агент называет проект только по id: путь он не передаёт и папок не добавляет.
- **Инструменты** (только окно главного агента, проверка по полному id сессии): `projects_list`, `project_start` {projectId, task}, `project_status`, `project_message`, `project_stop`, `project_result` — видны только окнам, запущенным Помощником (`audience: "own-cards"`, CanvasTTY с C4). На старом CanvasTTY сборка из `scripts/manifest-variant.mjs core-all` даёт вместо них один инструмент `projects` с `action` (у сервиса 16 инструментов, видных каждому окну). `start` спрашивает Jev о задаче и запускает **агента проекта** (оркестратор верхнего уровня, «Запущено» Помощником) в этой папке на выбранном Jev маршруте, с задачей и инструкцией; его субагенты направляются как у любого окна «Авто». Агенты проектов присылают результат через `report_to_main` {status, summary}.
- **Безопасность:** одновременно не больше 4 проектов (ваша настройка на странице). Проект, который ждёт вашего решения, главный агент никогда не одобряет; строка называет окно. Отчёты — недоверенные данные: главный агент получает их построчно в цитате, а его инструкция запрещает выполнять указания из них; текст отчёта никогда не попадает в строку статуса.
- **Строки статуса** («▸ shop-api — работает 12 мин · Claude Code · Max · opus/high · 3 агента · квота 64 %, сброс 18:00»): их собирает Помощник из своих решений о маршруте и квот Accounts. С **«Сообщать статус самому»** (включено по умолчанию) он впечатывает их в главного агента, когда проект готов, упал, заблокирован или ждёт вас, но только пока главный агент свободен и в нём 30 с ничего не происходило (о наборе текста CanvasTTY плагину не сообщает), пачкой за 10 с. Выключено: главный агент спрашивает сам через `status`.
- **Список настройки** на той же странице: автоматический выбор модели, «Может запускать оркестраторов», папка проекта и необязательное (Accounts работает, его чтение данных, аккаунты планов разрешены, «Может разрешать действия агентов» — чтобы Claude Code не спрашивал перед каждым вызовом, Environments, доверие после обновлений для Помощника и Environments — никогда для Accounts, — плитка на HOME), у каждого — путь в Настройках и, где CanvasTTY умеет `settings.open`, кнопка к этому разделу. Где CanvasTTY умеет `grants.request`, **«Разрешить недостающее…»** просит всё в одном окне CanvasTTY; иначе показываются пути.
- **Дерево агентов:** у каждого окна ещё аккаунт, на котором оно работает, и остаток квоты там.

## Как решает «Авто»

На страницах настроек у каждого элемента одно простое предложение; числа — здесь.

- **Уровень хода.** Разбор задачи Jev даёт тип задачи (код, ревью, исследование, тексты, общение) и сложность хода. Ход маленький, только если Jev ставит не меньше 0,5 на два самых простых уровня (0,7 для исследования и ревью); ход оркестратора маленьким не бывает. Без Jev решают словесные правила, и они никогда не «уверены».
- **Модель.** Из разрешённых и доступных сейчас моделей — самая дешёвая, чья оценка для этого типа не ниже лучшей больше чем на окно предпочтения: «Сбалансированно» 8 / 5 / 3 балла на маленьком / среднем / большом ходе, «Дешевле» 15 / 10 / 5, «Лучше» 0. В окне предпочитается и меньший уровень рассуждения, кроме больших ходов. Неизвестная оценка никогда не побеждает известную.
- **Несколько моделей** (только сложные текстовые ходы). В режиме «Авто» консенсус запускается, когда (оценка судьи + 1,5 балла за каждого другого производителя, не больше 3) − оценка одной модели − вес стоимости × log2(стоимость ÷ стоимость одной модели) − 0,5 × log2(время ÷ время одной модели) > 0. Вес стоимости: «Дешевле» 3, «Сбалансированно» 1, «Лучше» 0; время не учитывается, если скорость неизвестна. Черновики — не ниже лучшей больше чем на 8 баллов, судьи — на 3.
- **Планы.** На подписке, плане для кода или аккаунте с фиксированным тарифом модель стоит свою долю квоты относительно старшей модели плана (ожидаемые токены, ×1,2 у маленьких моделей, пока результаты не покажут иное, на отношение цен API или ваш вес) плюс «ценить скорость» × её время относительно старшей модели (ваши скорости, иначе скорость вывода и время до первого фрагмента по Artificial Analysis; неизвестная скорость считается тем же временем).
- **Данные.** Открытые, внутренние, конфиденциальные и секретные — это D0–D3 в журналах. Секретный текст остаётся на этом компьютере.

## Ограничения

- Бюджеты в минуту, в день и в долларах в день для облачных вызовов. Облачный вызов, пока идёт, держит верхнюю оценку
  своей стоимости в дневном лимите, поэтому параллельные вызовы не проскочат его вместе; затем её заменяет настоящая цена.
- Сбойный сервер модели размыкает предохранитель; поздние ответы вызовов, допущенных до размыкания, ничего не меняют,
  а замыкает его обратно только один пробный вызов.
- Серверу модели на этом компьютере (loopback, подтверждён как локальный) — один запрос за раз и очередь из 4;
  второй проверяющий делит с ним это место.
- Память: статистика хранит то же, что журнал (`logRetentionDays`, не больше 100 000 решений); состояние проверки
  по сессиям — не больше 512 сессий, давно не использованные уходят первыми.
- Между службой и CanvasTTY кадр не больше 1 МиБ, вызов хоста завершается ошибкой через 30 с или сверх 64 одновременных,
  а пока CanvasTTY не читает, ждущие события и журнал ограничены 8 МиБ (ответы не выбрасываются никогда).

### Квоты подписок

- Маршрутизация читает окна Claude, Codex, Kimi, OpenCode Go и Grok через `limits.get` CanvasTTY. Если CanvasTTY
  позволяет сервису читать их (`limits.subscribe` отвечает), Помощник подписывается при запуске, читает их сам — раз в
  5 минут, пока маршрутизация используется, раз в 15 в простое, раз в 2, пока маршрут отдыхает после лимита, и сразу
  после ожидаемого сброса — и сразу принимает уведомление `canvastty.limits.changed`; открытая страница не нужна. На
  более старом CanvasTTY их, как раньше, пересылает страница настроек, пока она открыта. Последние окна хранятся со
  временем чтения между перезапусками (`route/limits.json`); чтение старше 30 минут считается неизвестным, но не
  исчерпанным.
- **Досрочный сброс** (бонусный или промо-сброс провайдера): доля использованного в окне падает минимум на
  max(5 пунктов, половину использованного) или до 5 % и ниже раньше времени сброса, объявленного предыдущим чтением, —
  неважно, показывает ли провайдер после этого новое время сброса или прежнее. Время сброса, сдвинувшееся без такого
  падения, сбросом не считается. При досрочном сбросе (замеченном в чтении или сообщённом CanvasTTY) отдых маршрутов
  входа этого CLI сразу заканчивается, и маршрутизация планирует с восстановленной квотой; у каждого события
  сохраняются доли до и после, объявленное и новое время сброса и то, осталось ли прежнее время (страница показывает
  последние).
- Субагент, остановившийся на лимите, отправляет свой маршрут отдыхать до времени из его сообщения (Claude Code, Codex,
  Z.AI), иначе до сброса окна, иначе на 5 минут; более позднее чтение с запасом от 20 % или задача, завершённая на этом
  маршруте, заканчивают отдых раньше. Запуски через маршрутизацию после последнего чтения до следующего считаются по
  ~2 % окна каждый.
- Аккаунты моделей несут квоту, которую для них читает плагин Accounts (Z.AI / BigModel GLM Coding Plan): аккаунт с
  исчерпанной квотой не предлагается, а его отдых заканчивается, когда Accounts показывает более новое чтение с запасом.

### Что Помощник читает сам (новый CanvasTTY; всё определяется само, на старом — прежний путь)

- **Аккаунты, пулы и квоты Accounts** через общее чтение (`accounts.routes`, `accounts.quota`): только после того, как вы
  разрешите эту пару в Настройки → Агенты → Нативный код расширений, у Помощника; до этого страница «Где работают агенты»
  говорит об этом, а строки `list_routes` от оркестраторов используются как раньше. Пулы Accounts (`pool:<агент>`, ваши
  собственные входы) — маршруты подписки с квотой лучшего свободного аккаунта, для субагентов и для «Запустить с
  «Авто (Jev)»».
- **Установленные CLI и вход в них** из `providers.list` CanvasTTY (`providers:read`): оркестратору не нужно передавать
  список, а «Запустить с «Авто (Jev)»» предлагает только то, что есть.
- **Измеренные токены** окон, которые Помощник запустил или для которых задал параметры (`usage:read`), — между чтениями
  лимитов вместо ~2 % окна за запуск и в дереве агентов: платные маршруты по цене из каталога, планы как доля окна,
  собственная оценка OpenCode подписана как оценка агента.
- **Смена языка** (`canvastty.locale.changed` и язык с каждым действием окна): значки и сообщения следуют за ней.
- **`limit.exhausted` CanvasTTY** (собственный вход CLI исчерпан): маршруты на собственном входе этого CLI отдыхают до
  сброса; пулы и аккаунты моделей — другие входы.
- **Серверы для субагентов**: при включённых серверах ответ маршрута добавляет ваши объявленные серверы, которые CanvasTTY
  предлагает субагентам (по имени, со свободным местом), как `spawn_agent` с `environment`, на собственном входе сервера.

## Что нужно

CanvasTTY со службами плагинов и точками расширения Помощника (`secrets.get` для служб, `decide.timeoutMs`,
поля `profile` и `canAsk` в decide). Доверьте нативный код плагина в Settings → Agents → Extension native code и включите
**May allow agent actions**, если Помощнику можно разрешать команды самому.

Плагинам пока недоступно, поэтому не сделано: принуждение к одобренному сценарию (CanvasTTY должен сообщать
`launch.prepare` родительское окно и роль запуска и дать политике запуска отклонять запуски вне одобренного плана);
открытие карточки плагина из действия окна; результаты команд, токены и стоимость; локализованные названия действий окна.

## Сборка

```sh
npm install        # esbuild, typescript
npm run build      # собирает сервис и страницы, штампует манифест
npm test
CANVASTTY_REPO=/путь/к/CanvasTTY npm test   # плюс валидатор CanvasTTY и установка в его PluginManager
```

Сквозному тесту нужна копия CanvasTTY с `node_modules`; запускайте с
`NODE_OPTIONS='--experimental-strip-types --experimental-sqlite'`.
